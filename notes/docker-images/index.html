Custom Docker Images

Small servers and light servers (like AWS t2.small, etc.) which have a single vCPU and less than 2GB RAM are not able to run Docker images properly. Hence we generally build a custom image which is lightweight and could run on such systems. This presents a challenge as these machines cannot build and run this image from the Dockerfile instructions.

The idea to work around this limitation is to build the custom docker image on a different machine (or a CICD pipeline) in the required architecture and transfer it over to the target small capacity server for execution only.

#!/usr/bin/env/bash

# set -euxo pipefail    # dev only
set -o pipefail    # prod

IMAGE_TAG="0.1"
IMAGE_NAME="myApp"
PROJECT_DIR="."
DOCKER=$(command -v podman)
IMAGE_DIR="~/myApp/image"
DATE=$(date '+%d%b%Y-%H%M%S')

build_architectures=(
    "linux/amd64"
    # "linux/arm64"
    # "linux/arm/v6"
    # "linux/arm/v7"
)

# Colors
grn='\033[0;32m'
rst='\033[0m'

for platform in "${build_architectures[@]}"; do
    echo -e "\n\n${grn}Building for ${platform}${rst}"
    arch_suffix=$(echo "${platform}" | tr '/' '-')
    $DOCKER build \
        --force-rm --no-cache \
        --platform $platform \
        --tag $IMAGE_NAME:$arch_suffix \
        --file Dockerfile \
        $PROJECT_DIR

    $DOCKER save \
        --output "$IMAGE_DIR/$IMAGE_NAME-$arch_suffix.tar"\
        "$IMAGE_NAME:$arch_suffix"
        # --format docker-dir

done

One the custom image is built and saved as a tar file, it can be transferred to the small server via rsync and executed.

docker load --input "$IMAGE_NAME-$arch_suffix.tar"

docker run --rm -d --name $IMAGE_NAME -p 9999:80 \
    "localhost/$IMAGE_NAME:$arch_suffix"
